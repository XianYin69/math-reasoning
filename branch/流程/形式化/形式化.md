# 形式化（Formalize）

流程第一步：把自然语言问题改写为可推导的规格，未形式化不得进入求解。

## 必写四要素

| 要素 | 内容 | 检查 |
|---|---|---|
| 对象 | 涉及的集合、函数、序列、场、算子及其类型 | 每个符号首次出现即定义 |
| 假设 | 编号列出 `H1, H2…`（含正则性、定义域、边界条件） | 无编号假设视为缺失 |
| 记号 | 符号表 + 约定（量纲、单位、求和范围、范数定义） | 同一概念不得两个符号 |
| 目标命题 | 编号 `G1`，写成可判定真假的陈述句 | 禁止「说明为什么」类模糊目标 |

## 步骤

1. 复述问题为一句命题式陈述，标出量词与约束。
2. 拆出对象/假设/记号/目标四栏，缺项即向用户或题面补齐并标注来源。
3. 判定问题类型：证明 / 求解 / 估算 / 判定真假 / 构造反例。
4. 运行 `python scripts/formalize_check.py --spec <规格文件>` 校验四要素齐备。
5. 逻辑链留痕：`形式化 → 建模求解`，理由＝规格已齐且目标可判定。

## 禁止

- 未定义符号直接进推导；把结论当前提（循环论证）。
- 用记忆中的「标准结论」替代当轮推导（见 [红线](../../../resistance/红线/红线.md)）。
