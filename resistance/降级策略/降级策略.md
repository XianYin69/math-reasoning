# 降级策略（兜底路径）

执行期资源不可用时按本表降级；降级必须留痕（过程链 `interrupt` + 结果中标注缺口）。

| 故障 | 识别 | 降级动作 | 禁止 |
|---|---|---|---|
| 联网来源不可达 | 超时 / 403 / 404（如本轮 Wikipedia、Britannica） | 换可达源（本轮 arXiv API 可用）；仍不可得则退化为方法学自述，并在 [经验查询记录](../../references/经验查询记录.md) 记失败 | 编造引用或伪造访问日期 |
| 校验脚本缺失/报错 | 非零退出且非「存在缺陷」 | 手工按 [审查约束](../审查约束/审查约束.md) 对应项逐条复核，并说明未经脚本校验 | 跳过该项直接交付 |
| 数值不可得（无解析解） | 求解失败 | 转数值方案并给误差界/位数；仍不可得标 `待验` | 给无误差声明的近似值 |
| 自检不过 | 四项任一失败 | `process_chain interrupt` → 回炉 [证明链](../../branch/流程/证明链/证明链.md) | 降级措辞蒙混交付 |
| 重试达 10 次 | 同一步反复失败 | 惩罚熔断：回退当前分支或求助用户 | 继续无进展重试 |
| 前提不足 | 形式化缺项 | 向用户提问补齐；无法补则限定条件后标 `猜想` | 自行假设关键前提当已知 |

## 留痕要求

每次降级须写：触发条件、采取动作、对结论标签的影响（`已证/猜想/待验`）。
